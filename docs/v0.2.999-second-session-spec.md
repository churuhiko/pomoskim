# PomodoroOverlay v0.2.999 セカンドセッション仕様書

> この文書はv0.2.999時点の履歴資料です。v0.3では起動スプラッシュと関連アセットを廃止しています。現在の操作方法は[オンライン説明書](manual.html)を参照してください。

- 対象バージョン: v0.2.999
- 作成日: 2026-07-20
- 対象環境: Windows 11
- 仕様根拠: 本リポジトリの現行ソースコード、設定、テスト

## 1. 文書の目的

本書は、PomodoroOverlay v0.2.999 のセカンドセッションにおける開発・検証の基準を定める。旧タスク、旧セッション、過去チャットの内容は仕様根拠に含めない。記載内容と実装が矛盾する場合は、変更理由を明記したうえで本書または実装を更新し、両者を一致させる。

## 2. 製品概要

PomodoroOverlay は、作業画面の手前に常駐できる軽量な Windows 向けポモドーロタイマーである。通常のタスクバーボタンを持つフレームレスウィンドウとして動作し、作業時間と休憩時間の切り替え、Windows 通知、ローカル実績集計、任意の Google カレンダー記録を提供する。

## 3. セカンドセッションの基準

### 3.1 対象範囲

- v0.2.999 の現行機能を仕様化し、回帰を防ぐ。
- 現行の未コミット変更を含むワークスペース上のコードを実装基準とする。
- 既存のユーザー設定、実績、未送信レポートとの互換性を維持する。
- Windows 11 上でのソース実行および PyInstaller 配布物を対象とする。

### 3.2 対象外

- Google カレンダー上の既存予定の読み取り、検索、更新、削除、重複判定。
- 複数端末間の設定・実績同期。
- 日次の詳細履歴を恒久保存する分析機能。
- システムトレイへの格納。
- macOS、Linux、モバイル OS の正式対応。

## 4. 機能要件

### 4.1 タイマー

- 通常モードの作業時間は 25 分、休憩時間は 5 分とする。
- `Work 25m` と `Break 5m` でモードを切り替える。
- `Start` はカウントダウンを開始し、既に動作中の場合は二重開始しない。
- `Stop` は残り時間を保持したまま一時停止する。
- `Reset` は停止後、選択中モードの初期時間へ戻す。
- 完了時は実績を永続化してから通知処理を行う。
- 完了後は作業と休憩を自動で相互切り替えし、次モードの初期時間を表示する。次のタイマーは自動開始しない。
- モード変更、リセット、終了時に状態を保存する。

### 4.2 ウィンドウ

- 通常の Windows タスクバーウィンドウとして表示し、タスクバーへのピン留めを可能にする。
- 枠なし表示とし、オーバーレイの余白部分をドラッグして移動できる。
- 最小化、設定、完全終了の各操作を提供する。
- メインオーバーレイの「常に最前面に表示」は既定で有効とし、一般タブから切り替えられる。設定画面や外部アプリの操作では、この設定値を変更しない。
- 設定画面は最前面属性を持たない独立した通常ウィンドウとして表示する。
- 設定画面はモデルレスとし、表示中もメインオーバーレイの開始、一時停止、リセット、モード切替などを操作できるようにする。
- 設定画面は同時に1つだけ生成し、既に開いている場合は同じ画面を再表示する。
- 完全終了時の確認は既定で有効とし、設定で無効化できる。
- ウィンドウ位置、サイズ、Qt ジオメトリを保存し、次回起動時に復元する。
- ローカル TCP ポート `127.0.0.1:58432` の排他バインドにより、同時起動を 1 インスタンスに制限する。

### 4.3 表示設定

- 表示倍率は 100%、110%、120%、130%、140%、150% から選択する。
- 表示倍率は選択した時点で現在のメインオーバーレイへライブ反映し、直ちに設定ファイルへ保存する。設定画面の保存・終了を適用条件にしない。
- 表示倍率のライブ反映では現在位置、タイマー状態、進行状況を維持し、同一ウィンドウを再レイアウトしてサイズだけを更新する。
- 背景色はクリーム、セージ、ミストブルー、ダスティローズ、ソフトグレーから選択する。
- 背景色は選択した時点で現在のメインオーバーレイへライブ反映し、直ちに設定ファイルへ保存する。設定画面の保存・終了を適用条件にしない。
- 背景色のライブ反映では設定画面を維持し、メインの位置、サイズ、タイマー状態、進行状況、スキン、フォントを変更しない。
- 背景色に合わせて文字、境界線、ボタン、選択状態の配色を適用する。
- タイトル面とタイマー面は、選択した背景色系統の明るいバリエーションを使用する。
- Work／Break の選択中ボタンは通常ボタンよりわずかに明るくし、白文字の可読性を維持する。
- スキン固有の配色は持たず、スキン使用中も選択した背景色テーマの配色を適用する。
- スキンなし、または公式スキン「ポップ迷彩」「カーボン」「ギャラクシー」「ヘアライン」「ポップタイル」「武田菱」「フラワー」「ボタニカル」「クローバー」を選択できる。
- スキン選択画面は「カラー系」「ダーク系」「自然系」の3ページ構成とし、ウィンドウタイトルを `スキン選択/カラー系`、`スキン選択/ダーク系`、または `スキン選択/自然系` とする。
- カラー系には「ポップ迷彩」「ポップタイル」「武田菱」、ダーク系には「カーボン」「ギャラクシー」「ヘアライン」、自然系には「フラワー」「ボタニカル」「クローバー」を表示する。
- 「スキンなし（背景色を使用）」は全ページ共通で画面上部に固定し、ラジオボタン本体をクリックした場合だけ選択する。
- 各ページ内のスキン一覧は縦スクロール式でサムネイルと名称を表示し、各スキンのカード領域全体をクリックして選択できるようにする。
- ページ送りは「適用」「キャンセル」の直上に置く地の文リンク `＜＜`（前）と `＞＞`（次）で行う。移動先がないリンクは灰色かつ操作無効とする。
- `＜＜ ＞＞` の直上にはページ番号 `1 2 3` を地の文リンクとして表示し、番号をクリックすると該当ページへ直接移動する。現在ページの番号は灰色かつ操作無効とする。
- 設定画面から確定したスキンは、設定画面を閉じたりメインオーバーレイを再生成したりせず、その場でメインへプレビュー反映する。
- スキン選択ダイアログの「適用」で選択スキンを現在設定へ反映し、表示倍率の変更・再レイアウト後も同じスキンを維持する。
- 設定画面の「保存」でプレビュー中のスキンを永続化し、「キャンセル」またはウィンドウを閉じた場合は設定画面を開く前のスキンへ戻す。
- スキン使用時もタイトル面とタイマー面の可読性を維持する。
- 起動スプラッシュのイラストを設定画面から拡大表示でき、文字の閉じる操作または外側クリックで閉じられる。表示中はメインオーバーレイの最前面属性を一時解除し、イラストを最前面へ表示する。閉じると最前面設定を復元する。

### 4.4 通知

- Windows 標準のローカル通知を使用する。
- タイマー完了通知は既定で有効とする。
- 通知サウンドは既定で有効とし、無音通知へ切り替えられる。
- 作業完了と休憩完了で通知文を区別する。
- タイマー完了通知のクリック時は通知を閉じ、最小化中のアプリを復元して前面化する。
- 次のタイマー開始時は直前の完了通知を閉じる。
- 通知ライブラリの欠落または送信失敗はタイマー完了、実績保存、モード切り替えを妨げない。

### 4.5 設定画面

設定画面は次の 6 タブで構成する。

1. 一般: 常に最前面、完全終了確認、時間短縮モード。
2. 通知: タイマー完了通知、通知サウンド、Windows 通知設定の案内。
3. 表示: 表示倍率、背景色、スキン、スプラッシュイラスト表示。
4. 実績: 本日、当月、当年の作業・小休憩完了数、Google カレンダーへの手動書き込み。
5. 連携: Google カレンダーの接続状態、アカウント、未記録数、接続、カレンダー表示、解除。
6. ヘルプ: 操作チュートリアル、開発者連絡先、開発支援案内。

### 4.6 操作チュートリアル

- 初回起動時に 4 ページのチュートリアルを表示する。
- 戻る、次へ、完了のページ遷移を提供する。
- 初回表示時のみ `Skip` を提供し、完了またはスキップ後は自動表示済みとして保存する。
- ヘルプタブからは何度でも再表示できる。

### 4.7 起動スプラッシュ

- 起動時にバージョン、製品名、クレジット、イラストを表示する。
- 通常の表示時間は 1 秒とする。
- バンドル画像をバージョン単位のキャッシュへ初期準備し、準備が必要な場合は進行表示を行う。
- リモート更新は HTTPS、日次抑制、タイムアウト、キャンセル、容量・ハッシュ・寸法・形式検証、アトミック置換を前提とする。
- 更新失敗時は既存キャッシュを維持し、取得画像は次回起動から使用する。

## 5. 実績管理

### 5.1 集計単位

- 本日、当月、当年の 3 単位で次の値を保持する。
  - ポモドーロ完了数
  - 小休憩完了数
  - ズルのポモドーロ完了数
  - ズルの小休憩完了数
- 通常実績とズル実績は混合しない。
- 日付変更時に日次、月変更時に月次、年変更時に年次レポートを生成する。
- 同一 `report_id` の未送信レポートを重複登録しない。
- 365 日以上利用がない場合は、古い集計と未送信レポートを破棄して当日から再集計し、ユーザーへ通知する。

### 5.2 永続化

- 設定と実績は `%LOCALAPPDATA%/PomodoroOverlay/pomodoro_settings.json` に UTF-8 JSON で保存する。
- `LOCALAPPDATA` が利用できない場合は、ユーザーホーム配下の `.pomodoro_overlay/pomodoro_settings.json` を使用する。
- 不正な値は安全な既定値へ正規化する。
- 旧形式の当日カウンターは同日のデータに限り移行し、正確に再集計できない旧日次キューは引き継がない。
- 時間短縮モードの有効状態と短縮残り時間は保存しない。

### 5.3 実績タブ

- ポモドーロ完了数と休憩完了数を表示する。
- Google カレンダー連携による月報・年報の自動記録を案内する。
- 区切り線の下に「カレンダーに書き込み」ボタンを配置する。押下時は当日の日報を生成して未送信実績の同期を開始する。
- 手動書き込み操作ではブラウザーを自動的に開かない。

## 6. Google カレンダー連携

### 6.1 基本方針

- 連携は任意とし、OAuth スコープは本人所有カレンダーのイベントに限定する `calendar.events.owned` を使用する。
- 旧スコープの保存済みトークンは連携済みとして使用せず、権限縮小後の再認証を求める。
- プライマリカレンダーへ終日イベントを新規作成する一方向連携とする。
- OAuth トークンは設定ファイルと同じディレクトリの `google_calendar_token.json` に保存する。
- 配布物ではバンドルされた OAuth クライアント設定を使用し、ユーザーに JSON 選択を要求しない。
- 連携タブには「Googleカレンダーと連携」「Googleカレンダーに飛ぶ」「連携を解除」を配置する。
- 「Googleカレンダーに飛ぶ」は未連携時に灰色背景・黒文字で無効化し、連携済みの場合だけ通常の濃色ボタンとして有効化する。連携解除後は無効表示へ戻す。
- 有効時に押すと既定ブラウザーで `https://calendar.google.com/` を開く。

### 6.2 書き込み内容

- 日次イベント: 対象日、件名「ポモドーロ実績」。
- 月次イベント: 対象月末日、件名「YYYY年M月 実績」。
- 年次イベント: 12 月 31 日、件名「YYYY年 年間実績」。
- 説明欄に通常のポモドーロ完了数と小休憩完了数を記載する。
- ズル実績が 1 件以上ある場合のみ、ズル表記の件数を追加する。
- 通常実績が 0 件でも、ズル実績が 1 件以上あれば日報・月報・年報を未送信キューへ登録して書き込む。
- 手動書き込みは実績がすべて 0 件でも当日の日報を作成して書き込む。「書き込む実績がありません」ダイアログは表示しない。
- 当日の日報が未送信キューに既に存在する場合、手動書き込み時に通常実績とズル実績の両方を現在値へ更新してから送信する。

### 6.3 送信制御

- 未送信レポートは古いものから順番に送る。
- 1 件の送信に失敗した時点で後続送信を止め、失敗分以降を保持して再試行可能にする。
- 送信済みと確定したレポートだけを未送信キューから削除する。
- 日次メンテナンスは 60 秒ごとに日付変更と送信待ちを確認する。
- 起動直後には未送信キューを即時送信せず、通常の60秒周期またはユーザー操作を契機に同期する。
- 手動記録操作では同期を開始し、設定画面を最小化して既定ブラウザーでGoogleカレンダーを開く。
- 自動同期中に手動書き込みが行われた場合は、送信中の古い日報で最新日報を削除せず、現在の同期終了後に最新内容で再送する。
- 通信結果が不明な場合は重複作成の可能性を許容し、既存イベントの照合や削除は行わない。
- 連携解除時は確認を表示し、ローカル OAuth トークンを削除する。未送信実績は削除しない。

### 6.4 外部アプリ起動

- 設定画面からブラウザーまたは既定アプリを起動する直前に、設定画面を閉じずに最小化する。
- 対象は Google 認証、Google カレンダー、開発者連絡先、OFUSE、および将来追加する GitHub、PDF ヘルプ、更新ページなどの外部起動機能とする。
- 最小化には同じ設定ダイアログのインスタンスを使用し、位置、サイズ、選択タブ、入力途中の値を保持する。
- Google 認証は認証処理完了後、成功・失敗にかかわらず同じ設定画面を通常表示へ戻し、前面へ復帰させる。
- Google カレンダーなど通常の外部リンクでは設定画面を最小化したままにし、ユーザーがアプリへ戻した際に保持状態から再開できるようにする。

### 6.5 レポート通知順序

- 日報送信成功は短時間通知とする。
- 月報送信成功はユーザー操作まで保持する通知とする。
- 年報が同時に存在する場合、月報通知が閉じられた後に年報ダイアログを表示する。
- 年報ダイアログの後に Happy New Year 通知を表示する。
- 送信失敗通知は再試行を促すため保持し、同一失敗状態での連続通知を抑制する。
- 書き込み失敗通知には、Googleカレンダーとの再連携を試すよう案内を表示する。

## 7. 時間短縮モード

- `time_shortening.py` の `ENABLE_TIME_SHORTENING_MODE` が真の場合のみ設定画面へ表示する。
- 作業時間を 25 秒、休憩時間を 5 秒へ短縮する。
- 有効化・無効化時にタイマーを停止し、選択中モードの時間を再設定する。
- 時間短縮モード完了は通常実績ではなく専用カウンターへ記録する。
- 時間短縮モードは製品機能として既定で有効にし、設定画面から利用できるようにする。

## 8. 非機能要件

- 通知、ネットワーク、OAuth、キャッシュ更新の失敗はタイマーの基本動作を停止させない。
- Google カレンダー通信は UI スレッドを塞がないバックグラウンド処理とする。
- 完全終了時は新規バックグラウンド処理を禁止し、タイマー停止、ワーカー停止待機、Windows通知とコールバックの解除、イベントフィルターと単一起動ソケットの解放をQtオブジェクト破棄前に完了する。
- 認証情報、トークン、ローカル設定、ビルド生成物を公開リポジトリへ含めない。
- 配布版は未処理例外のスタックトレースを画面へ表示しない。カレンダー連携の失敗ログには生の例外本文、トークン、HTTP認証情報を含めない。
- UI は日本語を基本とし、主要操作名は画面表示とチュートリアルで一致させる。
- 高 DPI 環境でもタイマー文字が重ならないよう、描画フォント寸法から最低高さを算出する。
- 設定ファイルの破損、未知の背景色・スキン、負数・不正型の実績値を安全に処理する。

## 9. ビルドと依存関係

- Python 3.12 以降をソース実行環境の基準とする。
- GUI: PySide6 6.11.1。
- Windows 通知: Windows-Toasts 1.3.1。
- Google OAuth: google-auth-oauthlib 1.4.0。
- ソース実行: `python main.py`。
- テスト: `python -m unittest discover -s tests -v`。
- 配布ビルド: `python -m PyInstaller --noconfirm PomodoroOverlay.spec`。
- 配布物にはアプリアイコン、起動スプラッシュ、公式スキン、必要な OAuth 設定を含める。

## 10. 受入条件

1. 作業 25 分と休憩 5 分が開始・停止・リセットでき、完了後に次モードへ切り替わる。
2. 完了実績が通知より先に保存され、再起動後も保持される。
3. 表示倍率、背景色、スキン、通知、最前面、終了確認の設定が再起動後も反映される。
4. 初回チュートリアルが一度だけ自動表示され、ヘルプから再表示できる。
5. 日・月・年の境界で対応レポートが一度だけ未送信キューへ追加される。
6. Google カレンダー連携が既存イベントを読み取らず、終日イベントの新規作成だけを行う。
7. 途中送信失敗時に送信済みだけが削除され、残りが次回再試行される。
8. 通知またはカレンダー連携が失敗してもタイマーと実績保存が継続する。
9. 365 日以上の未使用後に古い実績と未送信レポートがリセットされる。
10. 自動テストがすべて成功し、PyInstaller ビルドが完了する。

## 11. セカンドセッション開始時の確認事項

- 変更着手前に `git status --short` で既存変更を確認し、無関係な変更を上書きしない。
- 仕様変更時は本書、実装、テスト、CHANGELOG の必要箇所を同一作業内で整合させる。
- 配布候補では時間短縮モードの表示名・時間・実績分離が仕様どおりであることを確認する。
- Google カレンダーの実送信試験では、重複イベントが作成され得ることを試験担当者へ周知する。
- リリース判定では自動テストに加え、Windows 11 の通知、OAuth、タスクバー、最前面、高 DPI 表示を手動確認する。
